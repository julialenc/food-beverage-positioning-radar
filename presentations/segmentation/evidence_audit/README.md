This supplement extends the v1.0.0 segmentation replay upstream through saved
images, provider observations, quality review, reconciliation and the claims
lock. It preserves the accepted analytical findings and v1.0.0. Segmentation
remains an **IN PROGRESS** research workstream; the website and Streamlit
application are unchanged.

## Important: 35-case historical evidence gap

**The 35 historical assessments reused in the locked claims retain saved OCR,
extracted results and provenance, but no retained original image bytes or raw
model envelopes were found.** Their image-to-original-model-response chain
cannot be reconstructed from this supplement. No missing originals were
invented or replaced with fresh provider responses. See the
[case-by-case register](historical_gaps.json).

Broader legacy CSVs are historical extraction records, not substitutes for
unretained transport envelopes. The supplement distributes all retained evidence
within its declared scope; it does not claim that every historical raw response
still exists. Human judgments and historical provider observations are fixed
evidence inputs, not judgments or paid calls regenerated by the replay.

## What is distributed

Every manifest entry has a path, byte count, SHA-256 and asset group. The assets
include selection/history records, cached images, execution SQLite ledgers,
saved OCR/model responses, prompts, archived source, review decisions, legacy
exports, governed starting inputs and the existing analytical package.

Timestamped raw OFF downloads, credentials, working environments and unrelated
trial databases are excluded. OFF data and images retain their attribution and
licensing (ODbL / CC BY-SA); original source URLs and hashes remain in the
selection/inventory records. Code and original project documentation retain the
repository's Apache 2.0 license.

The base source/data asset is the byte-preserved snapshot of commit
`e344c20221f2bba943a6fa6c97066705ecf1a1fb`, supplemented by the audit source
asset. Its older landing-page text is historical context. The root README was
subsequently restructured in `d92b0485`; no scientific code or input changed.
A Git clone alone does not contain the complete archive: download all 13 parts.

## Download and reproduce

Use a checkout of the **v1.1.0 tag**, Python **3.12.4**, and fresh directories.
Install the recorded pins into a virtual environment:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r presentations/segmentation/evidence_audit/requirements-evidence.txt
New-Item -ItemType Directory outputs/ocr_llm_download/assets
Copy-Item presentations/segmentation/evidence_audit/manifest.json outputs/ocr_llm_download/manifest.json
gh release download v1.1.0 --repo julialenc/food-beverage-positioning-radar --pattern "*.tar.gz.*" --dir outputs/ocr_llm_download/assets
.venv/Scripts/python.exe -I -B presentations/segmentation/evidence_audit/validate.py --candidate outputs/ocr_llm_download --workspace outputs/ocr_llm_download_replay
```

Alternatively, download all named parts manually from the release into the
`assets` subfolder. The validator checks part and file hashes before restoring
anything. Allow roughly **25 GiB free** for assets, restoration and results.
No provider credentials or unpublished analytical inputs are required.

The completed validation reused the recorded installed environment; a fresh pip
installation has not been certified. The environment stage checks the recorded
core analytical versions. The additional evidence-helper versions are recorded
in the requirements and validation report.

## Replay order and boundaries

Nine upstream checks cover ledger integrity/security, population reconstruction,
historical processing-history reconstruction, authorized image/selection
lineage, main-run quality export, dairy quality export, combined review, claims
reconciliation, and a fresh claims lock. The 25-stage v1.0 analytical replay then
rebuilds the master, findings and presentation tables from that claims layer.

All **34 checks passed**. The population/history tables, four claims-lock files
and master reproduced byte-for-byte. Remaining comparisons use the v1.0
numerical tolerances and documented metadata exceptions. Sampling choices and
human decisions stay fixed; exploratory selection-model fits and human judgments
are not repeated. No OCR/LLM provider calls occur.

Workers block network access, provider SDKs, subprocess dispatch, original-tree
reads and writes outside the disposable workspace. References and the frozen
analytical package in that copy are protected. Historical absolute paths are
relocated at I/O without editing the evidence. The offline harness disables an
unused urllib3 IPv6 import probe; outbound transport remains blocked.

## Maintaining the archive

The maintainer-only `package.py` assembles assets from original retained files;
it is not needed to reproduce a downloaded release. Data assets were not rebuilt
for publication. Only the supplemental source/documentation asset was refreshed
and rebound to the 52 executed scientific-source identities. Historical failed
harness attempts remain recorded; the final passing stages had zero actual
network/provider/subprocess/outside-write/original-tree-read denials beyond
intentional guard self-tests. Historical authorization records are evidence,
not permission for future paid execution.
